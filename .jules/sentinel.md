## 2024-05-24 - Authorization Bypass due to Undefined Environment Variable Interpolation
**Vulnerability:** The cron backups endpoint (`app/api/cron/backups/route.ts`) verified the incoming authorization token by comparing it against `Bearer ${process.env.CRON_SECRET}`. If `CRON_SECRET` was omitted from the environment variables, the string interpolation resulted in `"Bearer undefined"`, allowing an attacker to bypass the authorization check completely by sending an `Authorization: Bearer undefined` header.
**Learning:** Checking for environment variable existence is crucial when string interpolation is used for authentication or authorization tokens. If an environment variable is undefined, it resolves to the literal string "undefined", leading to fail-open behavior.
**Prevention:** Always explicitly check for the existence of required environment variables before attempting to validate against them. For critical secrets, fail securely (e.g., return 500 Server Error or 401 Unauthorized) when they are missing.
