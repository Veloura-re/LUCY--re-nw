## 2024-05-18 - Fail Open Security Configurations
**Vulnerability:** Found multiple instances where the codebase fell back to a default "dummy" test key if the environment variable was missing (e.g., Turnstile Secret) and an instance where a missing environment variable caused an authorization check to check against `Bearer undefined`. Additionally, database rate-limiting checks used generic `try/catch` blocks which silently suppressed errors (e.g. from table absence or query failure) which could be forced by an attacker to bypass rate limiting.
**Learning:** Hardcoded default fallbacks or string interpolations of missing environment variables fundamentally bypass the intended security mechanisms entirely without operators knowing. Catching all errors in security checks (failing open) makes the checks trivial to bypass if an attacker can manipulate conditions.
**Prevention:** Always check if critical environment variables are present and explicitly fail the request (HTTP 500) if they are missing. Avoid fallback test values. For security queries against a database, do not suppress errors generally; return an appropriate HTTP error code (503, 403, 429) unless explicitly catching a "missing function" during initial deployment.
