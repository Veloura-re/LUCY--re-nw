## 2024-05-18 - [Timing Attack in Webhook Signature Verification and Edge Environment Incompatibility]
**Vulnerability:** The Chapa webhook endpoint (`app/api/webhooks/chapa/route.ts`) was using a simple string equality check (`hash !== signature`) to verify HMAC signatures, which is vulnerable to timing attacks. An attacker could theoretically guess the signature byte-by-byte by measuring the time it takes for the comparison to fail. Additionally, the endpoint used the Node.js `crypto` module (`crypto.createHmac`) which is incompatible with the Cloudflare Workers / Next.js Edge runtime, causing potential build or runtime failures.
**Learning:** Standard string equality operators in JavaScript (`==`, `===`, `!=`, `!==`) perform short-circuit evaluation. This means the comparison stops as soon as a mismatch is found, leading to variable execution times based on the number of matching prefix characters. Also, the Node.js `crypto` module cannot be used in Edge routes; the standard Web Crypto API (`globalThis.crypto.subtle`) must be used instead.
**Prevention:** Always use constant-time comparison functions (like a custom `timingSafeEqual` implementation using bitwise XOR operations) when comparing security-sensitive values like cryptographic signatures, hashes, or tokens. Furthermore, exclusively use the Web Crypto API (`globalThis.crypto.subtle`) for all cryptographic operations in routes intended for the Edge runtime to ensure compatibility and stability.
