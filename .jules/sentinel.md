## 2023-10-24 - [CRITICAL] Fix "Fail-Open" Turnstile Security Bypass
**Vulnerability:** The authentication route (`app/api/auth/login/route.ts`) and client login page (`app/login/page.tsx`) both used a hardcoded dummy key (`1x00000000000000000000AA`) as a fallback if the Cloudflare Turnstile environment variables were missing. This created a "fail-open" vulnerability where missing configuration would bypass the intended CAPTCHA security protections entirely, allowing attackers to perform credential stuffing or brute-force attacks. Additionally, the Supabase Admin client fell back to `NEXT_PUBLIC_SUPABASE_ANON_KEY` if the service role key was missing, leading to a silent privilege drop during session updates.
**Learning:** Developers sometimes use dummy keys for local development to avoid configuration errors, but inadvertently leaving these in production code creates a severe bypass. Security mechanisms must always fail securely, blocking access if they cannot be initialized correctly. Similarly, privileged clients must strictly require privileged credentials and not fall back to unprivileged ones.
**Prevention:** Never use dummy keys or unprivileged keys as fallback defaults for missing environment variables. Implement strict checks for required security configuration during application startup or request initialization, and reject the operation (e.g., return HTTP 500) if the necessary secrets are unavailable.
