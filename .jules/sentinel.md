## 2024-05-18 - Rate Limit Bypass via x-forwarded-for manipulation
**Vulnerability:** The login endpoint rate limiting logic extracted the `x-forwarded-for` header and passed it directly to Postgres for an `inet` type cast (`::inet`). If an attacker passed multiple IPs separated by commas (e.g., `X-Forwarded-For: 1.2.3.4, 5.6.7.8`) or an invalid IP, the `inet` cast would fail. The query failure was caught by a generic `try/catch` block that suppressed the error, defaulting `rateLimitResult` to undefined and allowing the login attempt to proceed, completely bypassing the brute-force protection. Also, Cloudflare Turnstile token validation was vulnerable to parameter injection due to unsafe string interpolation in the request body.
**Learning:** Failing open on database query errors (especially rate limits) combined with improper input parsing (failing to extract the first IP correctly from proxy headers) allows attackers to easily bypass defensive layers.
**Prevention:** Always validate and parse IP addresses properly before using them in database queries (e.g., split by comma and extract the first valid IP). When security mechanisms like rate limits fail or error out, they should fail securely (deny access) rather than allowing the action. Additionally, use `URLSearchParams` for constructing URL-encoded API request bodies to prevent parameter injection.
