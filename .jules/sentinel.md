## 2026-10-05 - [Critical] Prevent Fail-Open with Turnstile Dummy Keys
**Vulnerability:** The login endpoint `app/api/auth/login/route.ts` used a Cloudflare Turnstile dummy key (`1x0000000000000000000000000000000AA`) as a fallback if the `TURNSTILE_SECRET_KEY` environment variable was missing. This dummy key always returns a successful verification from Cloudflare, effectively disabling bot protection entirely and failing open if the environment is misconfigured.
**Learning:** Hardcoding test keys as fallbacks for critical security infrastructure creates a severe fail-open vulnerability. It bypasses intended protections without any visible error, masking the misconfiguration while leaving the application vulnerable to automated attacks.
**Prevention:** Always ensure that missing critical security environment variables (like secret keys for bot protection, authentication, or authorization) cause the application or specific endpoint to fail securely (e.g., returning a 500 error) rather than falling back to a dummy or test value.
## 2026-10-05 - [Critical] Avoid Top-Level Stripe Initialization with Environment Variables
**Vulnerability:** Initializing the `Stripe` client at the top-level scope of a module (`lib/stripe.ts`) using an environment variable (`process.env.STRIPE_SECRET_KEY`) causes fatal build errors (`Error: Neither apiKey nor config.authenticator provided`) when compiling with OpenNext for Cloudflare environments. The static extraction and evaluation phase does not have access to these runtime environment variables, leading to silent initialization failures.
**Learning:** Top-level initialization using environment variables breaks static extraction in OpenNext/Next.js edge runtimes. Relying on side effects at module load time is dangerous and fragile in modern bundler environments.
**Prevention:** Implement lazy initialization using a singleton getter function (e.g., `let instance = null; export function getStripe() { if (!instance) instance = new Stripe(process.env.KEY); return instance; }`). This defers initialization until runtime when environment variables are properly populated.
